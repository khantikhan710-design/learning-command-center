# 可靠资料附件设计

## 目标

让“记录”页面只在图片、PDF 或 Word 已经真正持久化后显示为已附资料；云端和本机都无法保存时，仍可保存用户写下的资料卡正文，但不伪造附件已保存，并给出可执行的 Goodnotes/WPS 原件操作指引。

## 已确认的约束

- 当前 CloudBase 调用返回 `-601034`，因此不能把云存储当作可用附件仓库。
- `wx.saveFile` 的小程序本机存储总量只有约 10MB；PDF/Word 超过剩余容量时不能可靠长期保存。
- Goodnotes、WPS 及系统“文件”属于其他 App。微信小程序无法读取其内部资料、读取其列表或强制跳转并选中某一文件。
- `wx.chooseMessageFile` 可以让用户从微信会话中的文件里选取 PDF/Word；小文件可保存到小程序本机空间。

## 交互设计

### 来源不再伪装成自动联动

来源继续记录为资料卡的学习上下文，但选择后显示对应的真实导入方式：

- **Goodnotes**：提示先在 Goodnotes 中导出 PDF 到微信文件传输助手，再回到小程序点“选择文件”。
- **WPS 扫描**：提示在 WPS 中分享文件到微信文件传输助手，再回小程序选择；纸质照片改用“图片”。
- **纸质拍照**：直接启动小程序图片选择器，照片成功保存后才会写入资料卡。
- **其他**：允许用户选择文件或仅保存文字记录。

该入口只能引导用户完成跨 App 操作，不声明能够读取或自动同步第三方 App。

### 附件状态

每份附件必须有明确状态：

- `saved`：云端或本机保存已成功，可点开、转发或删除。
- `needs_source`：原文件没有保存进小程序；资料卡保留正文、文件名、大小和来源提示，但不提供“打开”承诺。用户可“重新选择原件”或删除该占位附件。

任何上传或本机保存失败都记录可读失败原因（例如云权限、文件超过本机 10MB 限额或系统空间不足），并先征询用户是否保留正文和创建 `needs_source` 占位附件。用户取消则不写入资料卡。

### 重新选择与替换

点 `needs_source` 附件时，操作菜单提供“重新选择原件并保存”“复制文件名”“删除这份附件”。重新选择成功后只替换这一份附件，不影响资料卡正文、日期、分类或其他附件。

## 数据设计

现有成功附件兼容保持不变：

```js
{ name, localFilePath, cloudFileID, type, attachmentId }
```

未持久化附件增加：

```js
{
  name,
  type,
  size,
  attachmentId,
  status: 'needs_source',
  reason: '文件超过本机可保存空间，请保留 WPS/Goodnotes 原件'
}
```

资料卡正文继续进入本机备份；`needs_source` 是元数据，不作为可恢复文件承诺。

## 错误与安全

- 云端失败与本机失败分别记录到开发者控制台，便于精确排查。
- 不展示已经失效的临时路径为“已保存”。
- 只有用户确认“保留正文”时，才写入无原件的资料卡。
- 删除占位附件与删除整张资料卡均继续二次确认。

## 验收

1. 小于剩余空间的文件走本机保存并能用 `wx.openDocument` 打开。
2. 本机保存失败时，不会显示“附件已保存”；用户可保留正文及显示明确的原件提示。
3. 选择 Goodnotes/WPS/纸质拍照会得到对应的实际导入引导，而非暗示自动同步。
4. 占位附件可单独删除或重新选择替换；替换成功后进入可打开状态。
5. 既有云附件与现有本机附件继续可打开、转发和删除。
