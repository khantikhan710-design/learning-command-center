# Goodnotes / WPS 资料卡 Design

## Goal

让“学习指挥台”成为个人学习的索引与复盘库，而不是另一套手写笔记软件。Goodnotes（及同类 iPad 笔记软件）和 WPS 保留原始资料；小程序集中保存资料属于什么、学到哪里、错因、重点与后续复习安排。

## User workflow

1. 用户在 Goodnotes 中刷题、手写演算；或在纸上完成题目后用 WPS 扫描。
2. 需要沉淀时，在“记录”页创建一张资料卡，选择来源：`Goodnotes`、`WPS 扫描`、`纸质拍照`、`其他`。
3. 用户选择已有学科分类，填写章节/标题和收获、错因或待解决问题；可选择关键图片、PDF 或 Word 文件。
4. 资料卡按学科收藏夹展示，卡片显示来源、日期、标题和附件数量；正文可复制，成功上传的附件可打开或转发。
5. 对于需要复习的资料，用户可从资料卡一键生成一条复盘，复盘保留资料标题、来源和资料卡引用；复盘页显示“来自资料卡”，返回后可打开对应资料。

## Chosen approach

采用“资料索引卡”，而不是全量复制 Goodnotes 笔记：

- 原始完整笔记继续留在 Goodnotes / WPS。
- 小程序优先存章节、错因、知识点、复盘结论与关键页。
- 完整 PDF 是可选附件，不作为每次学习的必填项。
- 不承诺调用或控制 Goodnotes；用户通过 iPad 的导出/分享或小程序选文件能力把关键资料加入资料卡。

## Scope

### Record page

- 新建资料卡字段：`source`、`title`、`subject`、`content`、`images`、`files`、`date`、`pinned`。
- 默认来源为“Goodnotes”；来源选择使用已有的小程序原生选择交互。
- 标题用于快速识别，例如“微积分：积分中值定理错题第 3 组”；正文继续记录错因、结论和待解决问题。
- 现有无标题记录继续兼容，列表以正文首行作为回退标题；历史记录的来源显示为“其他”。
- 资料卡按现有学科收藏夹折叠；卡片可复制正文、置顶和删除，并增加“转为复盘”。

### Review linkage

- “转为复盘”预填一条未掌握复盘：内容包含资料标题、来源和记录中的正文。
- 新复盘带 `recordId` 和 `sourceLabel`，用于回到关联资料卡。
- 资料已删除时，复盘仍保留自己的文字；“查看资料”按钮改为不可用提示，不删除复盘。

### Attachment and sync safety

- 图片、PDF、Word 仍使用云存储，只有云端上传成功后才写入 `cloudFileID` 并显示为“已附资料”。
- 当前 CloudBase 权限未恢复时，附件上传失败必须明确提示“附件未保存”；不显示成功、不生成虚假的文件链接。
- 不带附件的资料卡可正常保存在本机，供分类、复盘和本机备份使用。
- 对有正文的资料卡，如果附件失败，保留输入内容和所选文件在当前页面，用户可选择移除附件后只保存资料卡；不静默丢失已写文字。
- 跨设备附件、自动云同步属于 CloudBase 授权恢复后的能力；本阶段不绕过该限制，也不伪造同步状态。

## Data boundaries

- `studyRecords` 继续是资料卡的本机数据源；云端快照在可用时同步。
- 完整备份继续仅备份现有资料卡元数据和已经成功获得的云文件标识；本地临时文件不能作为可恢复附件承诺。
- 不新增第三方账号、API Key 或 Goodnotes 登录授权。

## Testing

- 为来源规范化、历史记录回退和“资料卡转复盘”新增纯工具测试。
- 覆盖：Goodnotes 来源、WPS 扫描来源、空标题回退、无附件正常保存、资料删除后关联复盘不丢失文字。
- 在微信开发者工具中手工验证：来源选择、创建资料卡、折叠收藏夹、转为复盘、附件上传失败提示和附件成功打开路径。

## Non-goals

- 不开发手写编辑器或替代 Goodnotes。
- 不实现自动读取 Goodnotes/WPS 数据、自动同步笔记内容或强制跳转；这些取决于第三方开放接口和系统能力。
- 不在本阶段处理小程序审核、发布、好友分享或大模型分析。
